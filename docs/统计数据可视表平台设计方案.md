# 统计数据可视表平台 · 设计方案

> 版本 v1.0 · 2026-11-07
> 产出方式：4 个调研智能体（政务领域 / BI 竞品 / 前端可视化 / 数据架构，参考 50+ 来源）→ 架构师 + 产品设计师并行出稿 → 红队评审挑战 17 项 → 综合定稿。

## 0. 三分钟看懂

**一句话定位**：面向国家数据局体系的"**指标中台 + 可视化分析平台**"——把分散在各主题、各地区、各行业的统计数据，统一成一套**口径唯一、可下钻、可联动、可指挥（大屏）**的数据消费体验。

**核心思路（三条）**：

1. **指标先行**：先建"指标字典"（每个指标有唯一编码、口径、责任人），图表只引用指标、不许自己写 SQL——从根上解决"同名不同义"这个政务数据的老大难。
2. **一切皆 JSON**：看板、大屏、图表全部是 JSON 配置，可版本管理、可下发到省级节点、可一键回滚。
3. **语义层是唯一出口**：所有查询必经语义层编译成 SQL（权限在这里注入、脱敏在这里执行、缓存在这里管理），前端与任何应用都不许直连数据库。

**总体架构一图流**：

```
┌────────────────────────────────────────────────────────────────┐
│ 前端层  门户 │ 驾驶舱 │ 主题看板 │ 自助分析 │ 大屏 │ 开放数据      │
│         React 18 + antd 5 + ECharts 6 + wujie 微前端             │
│         职责：渲染 JSON、管理交互状态，不含任何取数逻辑             │
├────────────────────────────────────────────────────────────────┤
│ 服务层  查询网关 │ 指标/维度服务 │ 看板服务 │ 导出(Puppeteer)      │
│         开放 API │ 统一鉴权 │ 受控取数 │ 审计日志                 │
├────────────────────────────────────────────────────────────────┤
│ 语义层  指标字典 │ 维度层级树 │ DSL 编译器(→SQL) │ RLS 注入        │
│         缓存(键=RLS指纹×数据水位×字典版本) │ 结果脱敏             │
│         ★ 全平台唯一口径出口                                     │
├────────────────────────────────────────────────────────────────┤
│ 数据层  DataX / Flink CDC → ODS → DWD 明细 → DWS(Doris 物化视图) │
│         → ADS 宽表(限量) │ DolphinScheduler │ Great Expectations │
├────────────────────────────────────────────────────────────────┤
│ 横切带  权限安全(RBAC + RLS + 数据分级) │ 血缘/监控/告警 │ 信创适配 │
└────────────────────────────────────────────────────────────────┘
```

**五个最重要的设计决策**：

| # | 决策点 | 结论 | 一句话理由 |
|---|--------|------|-----------|
| 1 | 自研 or 采购 | **语义层/指标字典自研，渲染层用开源，报表引擎评估采购** | 口径与下钻联动是核心资产，通用 BI 反而是包袱；但先用 6 周 bake-off 验证 |
| 2 | 下钻查询 | **事实表冗余层级列，下钻零 JOIN** | 每次下钻退化为"换 group by 列 + 等值过滤"，亚秒可达 |
| 3 | 国家-省级架构 | **元数据集中 + 数据联邦** | 数据不出省是政务底线，口径不失控是平台底线 |
| 4 | 联动机制 | **双轨制：全局筛选器单例 + 图表级事件总线** | 既保"改时间全板刷新"，又保"只联动 A 不联动 B" |
| 5 | 同环比 | **由指标元数据声明比较策略，语义层独占计算** | 比值指标先比子项再算比值，累计指标禁用环比——这是最容易出错的地方 |

## 1. 需求理解：谁在用，用来干什么

### 1.1 四类用户与核心场景

| 角色 | 典型场景 | 核心诉求 |
|------|---------|---------|
| **领导** | 打开驾驶舱总览 → 发现某省异常 → 下钻定位问题行业 | 零输入、纯点击、大屏可投屏 |
| **业务处室** | 进主题专区 → 设时间/地区筛选 → 联动分析 → 导出报告 | 下钻到县/小类、PDF 带口径脚注 |
| **数据分析员** | 自助交叉查询（指标×维度×过滤）→ 保存看板 → 申请发布 | 灵活取数、API、审批发布 |
| **公众/开发者** | 浏览脱敏后的开放数据看板 | 免登录、可下载、合规免责 |

### 1.2 主题域（对齐"数据要素×"与统计指标体系，10 个）

宏观经济运行 / 人口就业与民生 / 科技创新 / 能源与绿色低碳 / 资源环境 / 农业农村 / 城市治理与公共安全 / 交通·商贸·文旅·卫健等行业主题 / 政务数据资源目录与公共数据登记 / 数据要素市场（授权运营、开发利用）

### 1.3 维度模型（整个平台的"坐标系"）

```
地区维度   全国 → 省 → 市 → 县        （GB/T 2260 行政区划码，约 3000 节点）
时间维度   年 → 季 → 月               （当期值 / 累计值两种口径）
行业维度   门类 → 大类 → 中类 → 小类   （GB/T 4754：20-97-473-1382 四级）
部门维度   司局 → 处室 / 省级数据部门
数据属性   开放级别（无条件/有条件/不予）× 分级（核心/重要/一般，GB/T 43697）
```

**总览 → 下钻 → 联动 → 分析 → 导出**，就是在这套坐标系里自由移动。

## 2. 核心概念：六个名词撑起整个平台

```
主题域 SubjectDomain ──1:N──▶ 指标 Metric ◀──N:M──▶ 维度 Dimension
                                   │                     │
                              （唯一编码）          1:N 维度值 DimValue
                                   │              (code/parent/path/level)
                                   ▼                     │
                            数据集 Dataset ◀─────────────┘
                     (指标×维度×事实表绑定 + RLS 策略)
                                   │ 1:N
                                   ▼
                            图表 Chart (option_json + 联动声明)
                                   │ N:M (实例化，含样式覆盖)
                                   ▼
                     看板 Dashboard (layout_json + 全局筛选器)
                                   │ 复用
                                   ▼
                     大屏 Screen (1920×1080 画布 + 装饰件 + 轮播)
```

- **指标 Metric**：全平台的口径锚点。示例编码 `MACRO.GDP.VA0001`（宏观经济域·GDP·增加值）。三类：**原子指标**（事实字段+聚合）、**派生指标**（原子+时间修饰，如当期/累计/同比）、**复合指标**（多原子四则运算，如增速）。
  红队修正后，注册时**强制声明**两个关键字段：
  - `agg_type`：可加(sum) / 比值(ratio) / 累计(cumulative) / 快照(snapshot)
  - `compare_policy`：compare_then_compute（先比子项再算比值）/ window_sum / 禁止比较
  另有：口径公式、单位、责任处室、**口径依据文号**、更新频率、数据分级、脱敏规则、polarity（正逆指标）。
- **维度值**：扁平维表 + `parent_code` + **物化 path**（如 `/110000/110100/`）+ level，子树过滤一条 `like` 搞定。
- **数据集**：语义层的"事实绑定"单元——哪些指标、能切哪些维度、对应哪张事实表、挂哪条 RLS 策略。
- **图表**：只引用指标编码 + 维度分配（行/列/系列）+ ECharts option 覆盖 + `emits/subscribes` 联动声明。
- **看板 / 大屏**：纯 JSON（带版本），可导入导出、跨节点下发、diff、回滚。大屏与看板**同一份 JSON 双主题渲染**——暗色大屏给"看"，亮色报告给"办"。

## 3. 关键机制设计（本方案的硬核部分）

### 3.1 下钻：从全国到县、从门类到小类

**存储**：事实表直接冗余各级编码列（`region_prov / region_city / region_county`，`ind_c1~c4`）。

**为什么**：下钻时不需要 JOIN 维表，查询从"省"钻到"市"只是 `group by` 列从 `region_prov` 换成 `region_city`、WHERE 加一个 `region_prov='110000'`。代价是 ETL 多写几列、区划年度调整时重刷维表（调度固化），完全可接受。

**前端状态（吸收红队 B1 修正）**：**每个图表独立持有下钻状态** `{维度: 当前节点}`（A 图可以钻在行业 2 级，B 图钻在地区 3 级），不再是全局单栈：

- 三种入口发**同一事件**：点击图元 / 点面包屑 / 点维度树侧栏
- 面包屑按维度分段渲染：`全国 › 北京 │ 工业 › 制造业`
- 切换下钻维度时，原维度**降级保留为过滤器**而非丢弃
- URL 存**短编码的终态**（非事件序列），刷新/分享可还原；浏览器前进后退映射下钻历史
- 地图下钻复用同状态：全国→省→市→县，GeoJSON 按区划码懒加载，县级为最深层、点击改右侧抽屉

**后端查询**：DSL 里 `{dim:'region', path:'/110000', granularity:'city'}` 编译为 `WHERE region_prov='110000' GROUP BY region_city`。

**性能**：DWS 层物化视图按"地区×行业×月"预聚合，Doris 优化器自动改写路由——90% 的下钻查询亚秒返回，无需前端感知。

### 3.2 联动：cross-filter 事件总线

**协议**（pub/sub，看板内广播，消息幂等）：

```json
{ "type": "filter:click", "source": "chart-能耗行业构成",
  "payload": { "dim": "industry", "values": ["C制造业"], "op": "in" } }

{ "type": "drill:nav",  "source": "chart-地图", "payload": {"dim":"region","value":"110000","toLevel":"city"} }
```

**合成规则（吸收红队 B3 修正，写死冲突矩阵）**：

```
最终 WHERE = RLS ∩ 全局筛选 ∩ Σ cross-filter

同维度多事件   → last-wins（后到覆盖）
异维度事件     → 交集（AND）
下钻 × 联动    → 下钻栈保留，仅重算数据
全局筛选器变更 → 清空全部图表的 cross-filter 栈（上下文失效，语义无歧义）
cf 状态与下钻状态 → 一并压缩进 URL
大屏模式       → 禁用交互 emits，只保留数据订阅与脚本化轮播（防演示误触）
```

**视觉反馈**：源图元描边高亮；被过滤图表未命中数据变暗 35% + 去饱和 + 右上角漏斗角标（hover 显示来源图表）；全局筛选与图表筛选**分色胶囊**并列，可单个删、可一键清除；所有变化 300–500ms 过渡，禁止跳变。

### 3.3 同环比：最容易出错的地方，用元数据治

| 指标类型 | 错误做法 | 正确做法（本方案） |
|---------|---------|------------------|
| 可加型（GDP 总量） | — | 当期 vs 同期，直接比 |
| **比值型（增速、占比）** | 对结果值直接比 ❌ | **先比分子分母、再算比值**（compare_then_compute） |
| **累计型（1-6 月累计）** | 累计值环比 ❌（无业务意义） | **禁用环比入口**，只提供同比；UI 联动隐藏无意义操作 |

同环比计算**由语义层独占**，与下钻维度正交——下钻换维度时时间子句原样传递，任意层级口径一致；一次 SQL 多子查询（当期/同期/上期）算完。

**展示规范**：红涨绿跌（▲#D32029 / ▼#08979C，政务与资本市场阅读惯例），但铁律是"颜色只表方向，必须同显箭头+数值"，色弱可用；逆指标（能耗强度、失业率）在指标字典标 `polarity`，文案改"较上年上升"并可切警示语义。

### 3.4 权限与脱敏：编译期注入，前端永远不做安全

- **功能权限**：RBAC——角色 × 菜单 × API × 按钮。
- **数据权限（RLS）**：`角色 × 数据集 × WHERE 谓词` 存元数据库，**语义层编译时注入**（绝不走前端传参）。用户绑机构节点 → 谓词自动生成 `path like '本节点/%'` → 天然支持"省看全省、市看本市"。RLS 尽量收敛为"角色桶"而非按人（否则缓存命中率塌陷）。
- **脱敏**：规则挂指标元数据（低权限返回 `***`，半敏感取整/区间化），语义层在结果集执行。
- **缓存安全（红队 A3 修正）**：缓存键 = `RLS指纹 × 数据水位线(数据批次号) × 维度树版本 × 指标定义版本`。口径修订、区划调整、新批次入库三类事件主动广播失效，TTL 兜底。上线验收含"缓存红队测试"：改口径后 60 秒内全端可见。

### 3.5 查询 DSL（示例）

```json
POST /api/v1/query
{
  "metrics":  ["MACRO.GDP.VA0001", "MACRO.GDP.GR0001"],
  "dimensions": [{ "dim": "region", "granularity": "city" }],
  "filters":  [{ "dim": "region", "op": "descendantOf", "value": "110000" },
               { "dim": "industry", "op": "in", "values": ["C"] }],
  "time":     { "grain": "month", "range": ["2026-01","2026-10"], "compare": ["yoy"] },
  "sort":     [{ "by": "MACRO.GDP.GR0001", "order": "desc" }],
  "limit":    50
}
```

要点：指标**只允许引用注册编码**（禁止裸 SQL）；过滤器为 and/or/not 递归树；时间显式声明粒度以便路由到对应物化视图；所有聚合图表右键可 **drill-to-detail** 落明细兜底。

### 3.6 "必经语义层"如何不被绕过（红队 A2 修正）

制度约束靠不住，靠物理隔离 + 正门疏堵：

1. **物理**：Doris 集群网络隔离，集群内只存在语义层服务账号（FE ACL + 连接白名单）。
2. **正门**：提供"受控取数 API"——任意 SQL 强制包 RLS 视图 + 分级字段拦截 + 全量审计，满足"处室临时要个数"。
3. **迁移**：存量报表做 SQL→DSL 半自动翻译工具，按主题域定量排期。

## 5. 数据链路与查询加速

```
源系统(直报/名录库/普查/部门共享)
   │  DataX 批量(T+1) ＋ Flink CDC 增量
   ▼
ODS 贴源层（原样落库+分区+采集时间戳，保留全量历史用于重算与审计）
   ▼
DWD 明细层（清洗/标准化/统一国标编码；最细粒度：县×小类×月——口径追溯基准）
   ▼
DWS 汇总层（按"统计域×粒度"预聚合 + Doris 物化视图自动上卷）
   ▼
ADS 应用层（限量：仅 Top 高频看板预计算宽表；"能被物化视图覆盖就不建"）
   ▼
语义层（指标字典 + DSL 编译 + RLS/脱敏 + 缓存） ──▶ REST API ──▶ 前端
```

**加速三层递进**：① 库内物化视图自动路由（覆盖 90% 亚秒需求）→ ② Redis 热点缓存（键含版本指纹）→ ③ ADS 宽表（限量）。**指标体系按 OneData 方法论**：派生指标 = 原子指标 + 业务限定 + 统计周期 + 统计粒度。

## 6. 部署形态与信创

**信创替代矩阵**：CPU 鲲鹏/飞腾/海光 ｜ OS 麒麟 V10/统信 UOS ｜ 中间件东方通 ｜ 元数据库达梦 DM8 ｜ OLAP Doris ｜ 浏览器麒麟/奇安信/360。全栈无境外闭源运行时，前端库全 MIT/Apache 自托管。

**部署**：国家节点部署政务云专网区（等保三级边界：防火墙 + 堡垒机 + 数据库审计 + 日志留存 180 天）；公众开放数据独立 DMZ 区 + 脱敏 API + 限流。

**1+32 联邦**（国家节点 + 32 省级节点）：
- **元数据集中**：指标字典、维度树、看板模板国家唯一源，经政务外网下发（只同步元数据）
- **数据联邦**：各省属地存储、属地计算，仅回传汇总级数据集——"数据不出省"
- 编码命名空间预留省级扩展段（如 `BJ.MACRO.*`），字典同步 schema（版本/冲突规则）在 **MVP 期即冻结**（红队 D2 修正：契约前置，避免二期推倒重来）

## 7. 路线图（红队修正后的现实工期）

### 第 0 月：预备与 PoC（硬性前置）
- 信创三件套 PoC：①麒麟/统信自带浏览器兼容矩阵（wujie+antd5）②达梦方言差异清单 ③**Doris 鲲鹏基准压测**（数亿行、50 并发）——按结果调整基线
- 等保三级**定级备案第 1 个月启动**（流程 3-6 个月，不能等）
- 6 周 bake-off：3 个代表性看板"自研 vs 帆软采购"各做一遍 → 锁定自研边界

### MVP（第 1–5 月，5 个月）：内网试运行（豁免等保门禁）
**范围**：指标字典（只读检索）＋语义层 DSL（冻结范围：原子+一层派生、单事实表）＋2 主题域 50 指标＋地区/时间两维＋看板 JSON 渲染＋单维下钻+面包屑＋RLS 骨架＋管理闭环（**单一部门内**）＋冻结 1+32 字典同步 schema＋"黄金 SQL 用例集"（每指标 1 条人工核准基准 SQL，作为编译器唯一验收物）。

**DoD（无数字不验收）**：与源系统对账 100% 一致；明细查询 P95 ≤ 2s（千万行 @ 50 并发）；RLS 越权用例 100% 拦截；下钻 P95 ≤ 1.5s；黄金用例通过率 100%。

### 一期（第 6–11 月）：全量上线
**范围**：10 主题域 500 指标＋行业四级下钻＋联动总线＋大屏模块（暗色+轮播）＋天地图+审图号＋导出中心＋脱敏分级＋质量校验闭环＋跨部门口径审核流程（含统计局仲裁）＋**1–2 省人工方式试点联邦**。

**DoD**：等保三级测评报告+整改闭环；脱敏抽检 100% 通过；缓存红队测试通过（改口径 60 秒全端可见）；试点省实际运行。

### 二期（第 12–24 月）：生态与开放
**范围**：自助分析（拖拽建图+取数申请+审批发布）＋开放数据 API 门户＋1+32 联邦产品化（元数据自动下发）＋指标血缘与影响分析＋NL2Query（**限定为"自然语言→语义层词汇匹配"**：只允许命中已注册指标，未命中拒答并提示注册；敏感级默认拒绝；执行计划全量留痕）。

**DoD**：≥20 省级节点接入；开放 API ≥100 指标；血缘覆盖全部派生/复合指标。

### 止损触发器（写进立项文档，触发即切换采购，不再走审批）
| 触发条件 | 时点 |
|---------|------|
| 黄金用例通过率 < 90% 或 下钻+同环比 P95 超标 | MVP 第 2 月末 |
| 语义层核心人员流失 ≥ 1 人 | 任意时点 |
| 等保测评因语义层审计不通过 | 一期 |
| 省级试点无法运行自研栈 | 一期尾 |

## 8. 团队与治理

**团队（约 20 人核心 + 省市驻场 4–6 人滚动）**：架构师 1 ｜ 语义层后端 2（**强制结对、模块互换，禁止单人独占**）｜ 服务层后端 3 ｜ 看板/大屏前端 3 ｜ 组件与地图前端 1 ｜ 联动框架前端 1 ｜ 数据工程 3 ｜ DBA 兼信创运维 2（**+1 名 Doris 专职或购买商业支持**）｜ 测试 2（含安全渗透）｜ UI 1 ｜ PM 1 ｜ 另列预算：外聘 1 名 Headless BI/编译器背景顾问带教 2–3 个月。

**口径治理（红队 C1 修正）**：指标分两类——
- **法定指标**（GDP 等统计局口径）：锁定口径+依据文号，**只读引用不可改**，数据局无权"审核"
- **部门管理指标**：自主定义，注册强制填 Owner 处室、口径依据文号、数据来源责任人
- 会签 5 个工作日超时自动升级局领导并请统计局仲裁；MVP 只做单一部门内闭环，跨部门流程放一期

**需要决策人拍板的 5 个问题**：
1. 自研边界：接受"语义层自研（评估 Cube 内核）+ 报表引擎评估采购"的混合定位吗？第 6 个月切换采购的触发条件与预算是否现在锁进立项文档？
2. 口径主权：法定/部门指标边界、会签 SLA 与统计局仲裁机制，是否由局层面发文确认？谁对错数负首责？
3. MVP 基线：等保备案第 1 个月启动？MVP 明确为内网试运行？Doris 鲲鹏压测不过关时接受 x86 过渡吗？
4. 契约前置：1+32 字典同步 schema 在 MVP 冻结？一期承诺 1–2 省人工试点？
5. 人力单点：语义层 2 人强制结对+外聘顾问预算批准？Doris 专职/商业支持增补编制？

## 9. 多智能体讨论纪要（本方案怎么来的）

| 智能体 | 职责 | 关键产出 |
|--------|------|---------|
| 领域调研员 | 国家数据局/公共数据/合规 | 10 主题域、维度模型、4 类用户、合规红线（等保/信创/分级） |
| 竞品调研员 | 6 开源 + 5 商业 BI | 8 条可借鉴模式；"自研语义层+复用渲染"结论 |
| 前端调研员 | 图表/地图/布局/联动/大屏 | React+ECharts 6 技术栈组合；审图号/CGCS2000 合规 |
| 数据架构调研员 | OLAP/建模/语义层/加速 | Doris+星型+物化视图三级加速；DSL 设计要点 |
| 总架构师 | 综合出架构稿 | 分层架构、领域模型、下钻/联动机制、3 大决策 |
| 产品设计师 | 交互与旅程 | IA、5 旅程、交互规范、驾驶舱版式、红涨绿跌 |
| 红队评审 | 批判挑战 | 17 项修正（17 条全部吸收进本稿），5 个拍板问题 |

**关键争论与最终裁决**：
- 自研 vs 采购 → 分层混合 + 6 周 bake-off + 止损线（不赌）
- 全局单栈 vs per-chart 下钻状态 → per-chart（红队胜）
- 同环比通用后处理 → 指标元数据声明比较策略（红队胜）
- MVP 3 个月 → 5 个月（等保周期与信创 PoC 是硬约束）
- NL2SQL → 降级为 NL→词汇匹配（合规优先）
