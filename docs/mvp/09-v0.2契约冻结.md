## 1. 预警契约(T25)

```
GET /api/v1/alerts?asof=YYYY-MM
Header: X-Role: leader|prov-js|prov-gd
→ 200 {
  "asof": "2026-09",
  "watermark": "...",
  "computedAt": ISO时间,
  "items": [ {
    "province": "江苏省",      // dims.json name 全称
    "regionCode": "320000",
    "region": "江苏",
    "metricCode": "MACRO.MANUF.VA0001",
    "metricName": "制造业增加值(当月值)",
    "yoy": -4.5,               // 当月同比 pct
    "level": "danger|warning",
    "months": 5                // 连续负增长月数
  } ]
}
```

- 判定:ratio 型指标(agg_type=ratio 且 formula.num/den 存在)× 省(31省)× 当月:当月同比 < 0 → warning;连续 ≥3 月负 → danger。
- RLS:leader=31省;prov-js 只见江苏;prov-gd 只见广东。asof 缺省 = 当前 watermark 月。
- 逆指标(polarity=negative,仅 ENERGY.EI.VA0001):语义反转——当月同比 > 0 才预警(能耗上升=异常),连续≥3月上升 → danger。
- 服务端实时计算(每请求现算,与前端预埋 PRESET_ALERTS 无关),但必须覆盖预埋 3 组异常(A1 江苏制造业连续5月负,A2 能耗逆指标,A3 江苏垫底)。
- 前端消费:app.js `renderAlerts` 弃用 PRESET_ALERTS 常量,改为 fetch 该端点;行点击仍走 `drill:nav` 同事件同终态;C 区条形图"垫底标红"逻辑不变。

## 2. Doris 编译契约(T26)

```
POST /api/v1/compile
Header: X-Role
Body: QueryRequest(与 /api/v1/query 同 Schema)
→ 200 { "sql": "SELECT ...", "dialect": "doris", "executor": "local|doris",
        "cacheKey": "sha256:…", "warnings": [] }
```

- 编译器 `mvp/server/doris.js`(新建):QueryRequest → Doris 方言 SQL。
  - 物理表映射:`facts` → `dwd_stat_fact`
  - 层级列零 JOIN:region/province/city 层级冗余列(grain=province → GROUP BY province 列)
  - RLS WHERE 编译期注入;脱敏在投影层(mask 函数调用,登记 warning)
  - ratio 指标 = SUM(num)/SUM(den) 重算;compare_then_compute = 分子分母双窗口 SUM 后现算
  - 同比对比期窗口:`period >= '2025-01' AND period <= '2025-09'` 双窗口(或 *_py 列,与引擎一致)
  - LIMIT 2000 兜底;`/* watermark=… cacheKey=… role=… */` 注释头
- 执行后端 Executor 抽象:`getExecutor()` 按 env 选择——
  - `local`(默认):现有内存聚合路径不变,**黄金值一个都不能变**(回归 49/49 是硬门禁)
  - `doris`(DORIS_FE + DORIS_USER + DORIS_PASS + DORIS_DB 四 env 全配置时启用):Doris FE REST `POST {DORIS_FE}/api/query/{db}`(Header Authorization Basic, Accept: application/vnd.doris.query+json;v=1),body `{stmt: sql}`,NDJSON 流式解析;错误映射 10 错误码体系
  - shadow(DORIS_SHADOW=1 且 DORIS_FE 配置):双跑对账 local vs doris,不一致记 warning(本轮无法实测,只做代码就绪)
- `/api/v1/query` 响应新增 `meta.execution = {backend, sqlHash, durMs}`;`?debug=1`(或 `debug=1` body 字段)时附 `meta.sql` 全文。
- tests.js 新增:SQL 黄金快照 4 组(总览/province 下钻/city/ratio+同比)——固定 DSL → SQL 与快照逐字一致(编译器黄金测试)。

### 7.1 预警契约(T25)落位

- **编码落位**:契约示例编码 `MACRO.MANUF.VA0001`(制造业增加值当月值)在冻结注册表中落位为 **`MACRO.IND.VA0002`**(规上工业增加值,ind_va 仅存于 C 门类行,省级口径即制造业口径);契约示意编码 `ENERGY.EI.VA0001`(能耗逆指标)落位为 **`MACRO.ENGI.GR0009`**(单位GDP能耗降低率,冻结种子唯一 polarity=negative 指标)。判定规则本身元数据驱动,不写死编码。
- **预警指标集**:①ratio 型且 formula.num/den 存在(§1 判定主口径,读数=指标当月值,增速/同比类读数本身即同比语义);②sum 型(kind=sum,运行时 policy=direct/window_sum)(读数=当月同比 pct)。②为覆盖 §1 自身要求的三组预埋异常所必需——A1 载体即 sum 型当月值指标(契约 §1 示例条目 `yoy:-4.5, months:5` 与 facts.json A1 逐字对应)。累计/快照型无"当月"口径读数,不参与。
- **逆指标语义反转**:"当月同比 > 0 才预警"按指标口径落位——改善率型(公式 expr 含 `1 -`,即 GR0009 降低率)劣化 = **读数 < 0**(能耗不降反升,与数据字典 D5 载体、PRESET_ALERTS A2 "−12.48pct 逆指标变差"一致);若未来登记增长率型逆指标(如能耗消费量当月同比),劣化 = 读数 > 0(能耗上升=异常)。months = 连续劣化月数,≥3 → danger。
- **A2 实测读数**:引擎口径(Σ分子/Σ分母,全省全部 C 大类)2026-08/09/10 = −3.65/−5.62/−7.46,连续 3 月劣化 → danger;facts.json meta.stats 中 "−12.48" 为生成器目标口径(单大类同比比剔除口径),以服务端引擎值为对账基准。
- **A3 不落 alerts**:江苏 GR0001 累计增速 +3.88 为正读数,不满足 §1 "同比 < 0" 判定;且 PRESET A3 level=info 不在响应枚举 danger|warning 内。"垫底"叙事仍由 C 区排名条形图承载(§1 前端条款"垫底标红逻辑不变"),alerts 端点不重复表达。
- **asof 缺省** = 当前 watermark 月:watermark 日期所在月(wm-YYYYMMDD)与事实数据窗 [2025-01, 2026-10] 取交(越界夹取);当前水位 2026-11-08 → 默认 asof=2026-10。显式 asof 格式非法 → 400 DSL_SCHEMA_INVALID,越界 → 400 INVALID_TIME_RANGE(10 错误码体系)。
- **leader=31省**:种子仅 5 省,实现为"全部 level-1 省(现 5 省)"——维度表扩展到 31 省时端点自动覆盖,无需改码。每请求现算无缓存(§1 明示);items 按 regionCode+metricCode 字典序稳定排序。

### 7.2 Doris 编译契约(T26)落位

- **物理表**:`dwd_stat_fact` 单表,列 = `period`(月份)+ `region_prov/region_city/ind_c1/ind_c2`(层级冗余列,零 JOIN)+ 各原子字段(含 *_py 基值列)。行族门:ind 族指标 `ind_c2 IS NOT NULL`、region 族 `ind_c2 IS NULL`(对应本地 fact_ind/fact_region)。
- **确定性**:同 DSL → 逐字节同 SQL。固定:指标按规范化字典序编别名 m1..mN;compare 按字典序(mom<yoy)编 `mN_mom_base`/`mN_yoy_base`;窗口谓词单月用 `period = '…'`、区间用 `period >= '…' AND period <= '…'`;WHERE 以 `\n  AND ` 续行。tests.js 黄金快照 4 组(总览/province 下钻/city+RLS/ratio+同比)逐字节锁定。
- **双窗口**:WHERE period 取全部窗口(主窗+基窗)包络;各聚合一律 `SUM(CASE WHEN <窗口> THEN 列 END)` 守卫。sum 型基窗=时间平移窗(引擎 direct 同式);ratio compare_then_compute 基窗=同窗重算(*_py 列在基窗内,引擎 RATIO_SPECS 同式)。S4 快照即契约示例:`period >= '2025-01' AND period <= '2025-09'`。
- **基值换算**:SQL 只产 value 与 `*_base`;delta/rate 由执行侧按引擎同式现算(r2/r4;compare_then_compute 的 rate=null)——保持 49 断言黄金值算法单一来源。
- **脱敏投影层**:data_level ≠ "一般" 的指标投影以 `mask(…)` 包裹(Doris 侧 UDF 占位)并登记 warning(`MASK_APPLIED:<code>:data_level=…`)。冻结种子 16 指标均为"一般",warnings 常态为空,机制代码就绪。
- **Executor 抽象**:`getExecutor()` 每次调用现读 env。`local` 默认,黄金路径一字不改(回归 49/49 硬门禁);`doris` 四 env 全配置才启用,FE REST 失败统一映射 500 INTERNAL(detail 带 backend/reason/dorisStatus,不静默降级);`shadow` 双跑对账差异仅记审计,绝不改动 local 响应。本轮无 Doris 实例,doris/shadow 为代码就绪 + fixture 单测(NDJSON 解析、行映射、env 矩阵),未做真实联调。
- **meta.sql 兼容注记**:v0.1 起 meta.sql 常附于 query 响应,且 49 基线断言(D1/D15/DRILL)直接引用——为守住"黄金值一个都不能变"硬门禁,meta.sql 维持常附;`?debug=1`(或 body `debug:1`)语义 = 保证 meta.sql 全文可观测(doris 后端路径下即 Doris 方言全文),debug 不入缓存键/canonical。
- **LIMIT**:SQL 尾 `LIMIT <min(body.limit,2000)>`;Schema 已限 1..1000,2000 为编译器兜底上限。
