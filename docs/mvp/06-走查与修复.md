## 1. 缺陷修复记录（05 报告 §4 全部 4 项）

### BUG-01（一般·后端）meta.sql 编译产物列名与契约 §2.2.2 不一致

- **根因**：`index.js` 的 `GRAN_COL` 把粒度映射为**种子行字段名**（`prov/city/c1/c2`），`executeQuery`（内存行分组）与 `buildSql`（SELECT/GROUP BY 出口）共用该映射；而 WHERE 子句编译（`compileLeaf`）独立硬编码契约物理列名（`region_prov/region_city/ind_c1/ind_c2`）——同一条 SQL 两套列名混用。
- **修法**（最小改动，仅动 SQL 出口，内存聚合路径不变）：`buildSql` 出口新增 `SQL_COL` 映射（`prov→region_prov、city→region_city、c1→ind_c1、c2→ind_c2、month→month`），SELECT 与 GROUP BY 统一走契约列名，与 compileLeaf 的 WHERE 列名对齐。同步把 `tests.js` 原写死种子名的断言 `/GROUP BY prov/` 更新为 `/GROUP BY region_prov/`（该断言原是按缺陷行为写死的）。
- **验证**：POST /query（下钻江苏×制造业）→ `SELECT region_city AS dim_region, SUM(gdp_va) AS m1 FROM fact_ind WHERE region_prov = '320000' AND ind_c1 IN ('C') AND month = '2026-10' GROUP BY region_city`——WHERE/SELECT/GROUP BY 三处全为契约名；回归 D1 两条 SQL 断言（无 JOIN、物理列名）均 PASS。

### BUG-02（建议）"口径不适用"返回语义：metrics.json 声明 vs 实际行为

- **根因**：metrics.json `MACRO.IND.VA0002` 的 `store.rows` 描述写"I/M 门类无此口径，查询返回空集"，实际语义层对口径不适用组**保留返回行、value=null**（`sumField` 窗口内无该字段任何行 → null）。行为本身与前端空值渲染（"—"）自洽，属文档描述误导。
- **修法**（选择"改动小且与契约一致"的一侧——改数据文档描述＋契约补注，不动查询语义）：① metrics.json 描述改为"c1=C（I/M 门类无此口径：口径不适用组保留返回、value=null，见契约 03 §2.3 修订注）"；② 契约 03 §2.3 在"空结果集"段后新增【T09 修订】段，明确"口径不适用"（组行存在、支撑字段无取值 → `value=null`、yoy/mom 缺省）与"空结果集"（组行不存在 → `data:[]`）为并列的两种空语义，`value` 字段类型标注改为 `number | null`。
- **验证**：tests.js D17c 断言（200、rows=3、全 null）原样通过；curl 实测 I 门类 → rows=3、value 全 null、SQL 契约列名。

### BUG-03（建议）种子规模与 PRD §2.3 冻结范围不一致未登记

- **根因**：实际种子为 5 省 20 市（每省 4 市）、3 门类 10 大类、2025-01～2026-10 共 22 个月（PRD 原声明 31 省全量+3 省 55 市、5 门类、34 个月）；roles.json/T02 已自声明缩减，但 PRD §7.1 范围变更登记区为空，权威口径缺位。
- **修法**：PRD §7.1 登记第 1 条：种子范围缩减明细（缩小方向属 §2.6 允许），理由"原型演示最小充分"，并注明演示叙事"31 省排名"以实际 5 省为准。注：05 报告表述"12 大类"与 dims.json/metrics.json 实际（10 大类）不符，登记按 10 大类为准。
- **验证**：文档登记完成；GET /meta/dims?dim=region（leader）→ count=5 与登记一致。

### BUG-04（建议·文档）前端 hash 路由与 PRD §5.0 path 路由不一致

- **修法**（按缺陷建议"文档回写"侧）：04 规范 §5.1 已固化 hash↔path 映射表；本次在 PRD §7.1 登记第 3 条，声明 P0 采用 hash 路由为 §5.0 语义路径的实现名（`#/cockpit、#/theme/:domain、#/dict` ↔ `/cockpit、/topic/:domain、/dictionary`），生产迁移换 path 路由+服务端 rewrite、注入点不变。
- **验证**：实测未知 hash `#/xyz` 自动重定向 `#/cockpit`（本次走查顺带补齐的实现项，见 §2-W6）。
