## 1. 背景与 MVP 目标

### 1.1 一句话背景

平台定位是"指标中台 + 可视化分析平台"：指标口径唯一、可下钻、可联动、可指挥。全部查询必经语义层编译成 SQL，前端不许直连数据库（设计方案 §0 三条核心思路）。

### 1.2 MVP 要验证的四个假设（本原型存在的理由）

| # | 假设 | 验证物 |
|---|------|--------|
| H1 | DSL 契约（指标编码 + 维度 + 过滤 + 时间）足以表达 P0 全部页面取数，且编译结果与人工核准 SQL 一致 | 黄金用例集 100% 通过 |
| H2 | 下钻 / 联动 / 同环比 / RLS 四大机制在"同一语义层出口"下语义自洽、不互相打架 | DoD 走查（§3） |
| H3 | 领导旅程 J1（零输入、纯点击、五步异常溯源）在 3 个页面内闭环 | 演示脚本实跑（§6） |
| H4 | 口径治理载体（指标字典元数据：agg_type / compare_policy / polarity）能被机器执行而非纸面约定 | D3–D5、D16 自动断言 |

### 1.3 明确不验证的（留给生产 MVP，见 §4 风险 R3）

性能指标（下钻 P95 ≤ 1.5s、明细 P95 ≤ 2s @ 千万行 50 并发）、等保、信创适配、Doris 物化视图路由、1+32 联邦下发。原型用内存数据，只验**机制正确性**，不验性能与部署。

## 2. P0 范围冻结

**冻结即纪律**：下表任何一项的扩大（加指标、加主题域、加页面、加维度层级）都视为范围变更，需重新评审；本阶段只允许缩小。

### 2.1 冻结总表

| 冻结项 | P0 范围 | 依据/说明 |
|--------|---------|-----------|
| 主题域 | **2 个**：宏观经济（MACRO）、科技创新（TECH） | 设计方案 10 个主题域中选领导使用频度最高、口径最成熟的 2 个；其余 8 个放一期 |
| 指标 | **≤16 个**（实际冻结 16 个，见 2.2） | 比设计方案 MVP 的 50 指标进一步收窄：16 个足以覆盖全部 agg_type × compare_policy 组合，每个都有黄金 SQL 用例 |
| 地区维度 | **两级**：全国 → 省 → 市（GB/T 2260） | 不做县级（设计方案四级中的后两级放一期） |
| 时间维度 | **月粒度**，区间 2024-01 ～ 2026-10 | 只做月；年/季粒度放一期。当期值/累计值口径由指标定义声明 |
| 行业维度 | **两级**：门类 → 大类（GB/T 4754-2017） | 不做中类/小类（放一期） |
| 页面 | **3 个**：领导驾驶舱、主题看板、指标字典 | 自助分析、大屏、开放门户全部不做（§7） |
| 角色 | **2 个**：领导（全国数据）、省用户（本省数据，RLS） | 不做市级用户、不做按人授权（RLS 收敛为角色桶，缓存友好） |
| DSL 范围 | 原子指标 + 一层派生、**单事实表**、无 JOIN | 与设计方案 §7 语义层选型冻结范围一致 |
| 验收物 | 每指标 1 条人工核准基准 SQL（黄金用例集） | 编译器唯一验收物（设计方案 §8 MVP 条目） |

### 2.3 维度与数据种子（原型）

| 维度 | 层级 | 原型种子 | 生产目标 |
|------|------|---------|---------|
| 地区 region | 全国 → 31 省 → 地级市 | 全国 + 31 省全量；**江苏 320000、广东 440000、四川 510000 三省含全部所辖地级市**（共 13+21+21 市），其余省市级数据不种 | 全国→省→市→县四级 |
| 时间 time | 月 | 2024-01 ～ 2026-10（34 个月，保证同比与长趋势可算） | 年/季/月 |
| 行业 industry | 门类 → 大类 | 5 个代表性门类（B 采矿、C 制造、D 电热气水、F 批发零售、I 信息技术）+ 每门类 6–10 个大类 | 20 门类/97 大类/中类/小类 |

存储按设计方案 §5.1：**事实表冗余层级列**（`region_prov / region_city / ind_c1 / ind_c2 / month`），下钻零 JOIN——换 group by 列 + 加等值过滤。

### 2.4 角色与 RLS

| 角色 | 原型演示账号 | RLS 谓词（语义层编译时注入，前端不传） | 可见效果 |
|------|-------------|------------------------------------------|---------|
| 领导 leader | `leader` | 无（全量） | 驾驶舱显示全国：31 省排名、全国指标卡 |
| 省用户 province | `prov-js`（江苏）、`prov-gd`（广东） | `region_path like '/320000/%'`（由账号绑定的机构节点自动生成） | 同一 URL：指标卡=本省口径，排名表=本省所辖市排名，维度树只显示本省子树 |

规则：RLS 谓词**只能来自服务端账号绑定，绝不接受前端传参**（设计方案 §5.4）；越权请求（省用户显式过滤他省）返回空集而非报错（§3 D7）。

### 2.5 冻结的 DSL 契约范围（与生产一致的子集）

```
POST /api/v1/query
{
  "metrics":    ["MACRO.GDP.VA0001", ...],            // 只允许注册编码，禁止裸 SQL
  "dimensions": [{ "dim": "region", "granularity": "prov" | "city" },
                 { "dim": "industry", "granularity": "c1" | "c2" }],
  "filters":    [{ "dim": "region", "op": "descendantOf", "value": "320000" },
                 { "dim": "industry", "op": "in", "values": ["C"] }],   // AND 合成
  "time":       { "grain": "month", "range": ["2026-01","2026-10"],
                  "compare": ["yoy","mom"] },          // mom 对 cumulative 指标被拒绝
  "sort":       [{ "by": "<metricCode>", "order": "desc" }],
  "limit":      50
}
```

编译语义（本 PRD 冻结，原型与生产共用）：`最终 WHERE = RLS ∩ 显式过滤 ∩ (下钻等值条件)`；同环比在语义层独占计算（一次查询多子查询返回当期/同期/上期）；缓存键 = `RLS指纹 × 数据水位线 × 维度树版本 × 指标定义版本`。

### 2.6 范围变更控制

- P0 冻结后，新增指标/主题域/页面/维度层级 → 记入 §7 待办，不进本迭代。
- 发现机制缺陷（如 DSL 表达力不足）允许**修契约**，但必须同步更新黄金用例集并全量回归——契约变更的唯一合法路径。

## 3. 用户故事与验收 DoD（给定/当/则）

**读法**：每条 DoD 用"给定（前置状态）/当（触发动作）/则（可观测结果）"表述；`验证` 列 A=自动断言（脚本可判）、M=人工走查（评审现场判）。语义层所有响应携带 `meta`（编译产物 SQL、缓存命中标记、口径版本、耗时），既是断言依据也是演示素材。

### US1 DSL 查询正确（图表不写 SQL，口径唯一出口）

> 作为前端图表，我希望只引用注册指标编码 + 维度 + 过滤 + 时间即可取数，以便不写 SQL 也拿到口径唯一、与人工核准一致的结果。

| # | 给定 | 当 | 则 | 验证 |
|---|------|----|----|------|
| D1 | 黄金用例集（16 指标 × 1 条人工核准基准 SQL）已就绪 | 对同一 DSL 请求原型语义层编译执行 | 逐行数值与基准 SQL 结果 100% 一致；且编译产物 SQL 断言**无 JOIN**——下钻仅表现为 group by 列替换 + 等值过滤追加 | A |
| D2 | DSL 请求引用未注册编码、或夹带裸 SQL 片段 | 提交 `POST /api/v1/query` | 返回 4xx 与明确错误文案（"指标编码未注册"），不产生任何数据查询；审计日志留痕 | A |

### US2 同环比按 compare_policy（元数据治比较，语义层独占计算）

> 作为业务分析者，我希望同环比严格按指标声明的 compare_policy 计算，以便比值型不被"对结果直接比"误导、累计型不出现无业务意义的环比。

| # | 给定 | 当 | 则 | 验证 |
|---|------|----|----|------|
| D3 | 比值型指标（如 MACRO.GDP.GR0001，compare_then_compute），演示数据中分子分母同期异动 | 请求该指标 yoy | 语义层先分别取分子/分母的当期与同期值、再算比值差；结果 ≠ 对结果值直接相减的错法（构造数据使两者差 ≥ 0.1pct，断言采用前者） | A |
| D4 | 累计型指标（如 MACRO.INV.CU0004） | ① DSL 的 time.compare 含 "mom" 提交 API；② 在 UI 上打开该指标的比较菜单 | ① API 返回 4xx"累计型指标禁用环比"，仅接受 yoy；② UI 的环比入口置灰隐藏，同比入口可用 | A |
| D5 | 逆指标（MACRO.ENGI.GR0009，polarity=inverse），演示数据中其值同比上升（变差） | 该指标出现在指标卡/图表 | 按警示语义展示：箭头+数值同显（颜色只表方向，色弱可读），文案为"较上年上升 X pct"而非"增长"；正指标按红涨绿跌（▲#D32029 / ▼#08979C）+ 箭头数值同显 | A+M |
| D6 | 已处于任一下钻状态（如 江苏 → 市级） | 对比值型指标请求 yoy | 时间子句原样传递、与下钻维度正交；市级同比与全国/省级口径一致（一次查询多子查询返回当期/同期/上期，结果与黄金 SQL 一致） | A |

### US3 RLS 裁剪（编译期注入，前端永远不做安全）

> 作为省用户（prov-js），我希望默认且仅能看到本省数据，以便满足"数据不出省/最小可见"合规要求。

| # | 给定 | 当 | 则 | 验证 |
|---|------|----|----|------|
| D7 | 账号 prov-js（绑定江苏 320000） | 显式提交过滤 `region descendantOf 440000`（广东） | 返回 HTTP 200 + **空结果集**（0 行），不报错、不泄露他省数据是否存在 | A |
| D8 | 账号 prov-js 打开领导驾驶舱/主题看板 | 页面取数 | 指标卡=本省口径；排名表=本省所辖市排名；维度树只显示本省子树；响应中不存在任何 `region_path` 不以 `/320000/` 开头的数据行 | A |
| D9 | 请求体或 URL 中携带任意伪造的 `rls` / `region` 授权参数 | 提交查询 | 服务端**完全忽略**，RLS 谓词只来自账号绑定的机构节点（编译期注入），行为与不带参数时逐字节一致 | A |

### US4 缓存命中与失效（键=版本指纹，口径修订全端可见）

> 作为平台运营者，我希望口径修订/新数据入库后旧缓存立即失效，以便"改口径 60 秒内全端可见"（原型为立即生效）。

| # | 给定 | 当 | 则 | 验证 |
|---|------|----|----|------|
| D10 | 同一 DSL 请求（同账号）首次执行完毕 | 立即再次执行同一请求 | 第二次响应 `meta.cache=hit`、耗时显著下降；缓存键含 RLS 指纹——leader 与 prov-js 同一 DSL 命中**不同**缓存条目 | A |
| D11 | 某查询已被缓存 | 通过调试面板触发任一失效事件：①指标定义版本 bump（模拟口径修订）②数据水位线 bump（模拟新批次入库）③维度树版本 bump（模拟区划调整） | 同一请求重新编译执行、`meta.cache=miss` 并返回新结果；三类事件对旧键全部失效，TTL 仅兜底 | A |

### US5 下钻路径（三入口同事件，URL 存终态）

> 作为领导，我希望点一下排名条形就钻到该省，且面包屑/URL 随时可回退、可分享，以便零输入完成溯源。

| # | 给定 | 当 | 则 | 验证 |
|---|------|----|----|------|
| D12 | 用户已下钻（全国 → 江苏 → 市级 + 行业门类→大类） | 复制当前 URL 到新标签页打开 | 页面还原**同一终态**：面包屑、各图表层级、过滤胶囊、明细表全部一致（URL 存短编码终态而非事件序列）；浏览器前进/后退逐级回退 | A+M |
| D13 | 主题看板已加载 | 分别通过 ①点击图元 ②点面包屑 ③点维度树侧栏 三种入口下钻 | 三种入口发出**同一事件**、产生同一状态迁移与同一 URL 终态；面包屑按维度分段渲染 `全国 › 江苏 │ 行业 › 制造业`；切维度时原维度降级保留为过滤器（不丢弃） | M |

### US6 联动过滤（cross-filter 事件总线）

> 作为看板使用者，我希望点行业构成图的"制造业"，其他图表自动切换为制造业口径，以便交叉定位问题行业。

| # | 给定 | 当 | 则 | 验证 |
|---|------|----|----|------|
| D14 | 主题看板内行业构成图与市级排名图、月度趋势图共存 | 点击行业构成图"制造业"图元 | 发出 `filter:click {dim:industry, values:["C"]}`；订阅图表重取数、结果仅含制造业（响应断言）；源图元描边高亮，被过滤图表未命中数据变暗 35%+漏斗角标；过滤胶囊出现且可单个删 | A+M |
| D15 | ①已存在行业 cross-filter，再次点击"批发零售" ②存在 cross-filter 时改变全局筛选器（时间范围） | 观察最终 WHERE 合成 | ① 同维度 last-wins（后到覆盖，非并集）；② 异维度事件 AND 交集；③ 全局筛选器变更**清空全部图表 cross-filter 栈**；合成规则恒为 `RLS ∩ 全局筛选 ∩ Σ cross-filter`，下钻栈保留仅重算数据 | A+M |

### US7 页面可载入与字典可检索

> 作为演示评审者，我希望三个页面都能一键打开无报错，指标口径随手可查，以便现场验收不被阻断。

| # | 给定 | 当 | 则 | 验证 |
|---|------|----|----|------|
| D16 | 16 个指标已按 §2.2 元数据注册（agg_type/compare_policy/polarity 为结构化字段而非文档描述） | ① 请求字典 API；② 在字典中临时新增一个测试指标（含 polarity=inverse）不改动任何前端代码 | ① API 返回全部元数据字段完整；② 驾驶舱/看板按新指标自动渲染出正确比较入口与警示语义——渲染完全由元数据驱动 | A |
| D17 | 原型服务已启动，两个演示账号可用 | 逐一打开 驾驶舱 / 主题看板（宏观经济、科技创新两个实例）/ 指标字典 共 4 个路由（3 页面） | 每页 HTTP 200，全部图表完成渲染，浏览器 console 无错误；空数据显示"当前筛选下无数据"+清除按钮，加载超 3s 显示文案 | A |

## 4. 原型技术路线决策

### 4.1 结论

**确认采用**："零构建 vanilla JS 前端 + 本地 ECharts 文件 + 零依赖 Node 语义层服务（Node 内置模块实现，无 node_modules）"。生产栈维持设计方案定论（React 18 + antd 5 + ECharts 6 + Spring Boot + Doris），**不受原型路线影响**——原型只为验证 §1.2 的 H1–H4，不是生产代码的起点。

### 4.2 三条理由

1. **内网离线可跑**：目标演示环境是政务内网/隔离笔记本，无 npm registry、无 CDN。零构建路线 = 一个目录拷走即跑（`node server.js` + 浏览器打开），不依赖任何网络安装步骤——这是演示能否"现场发生"的硬约束。
2. **零安装、零环境损伤**：不需要 Node 之外的任何运行时，不留 node_modules、不锁包版本、不需要构建链知识即可被评审方自行启动复现。演示可信度来自"可复现"。
3. **语义层 DSL 契约与生产一致**（本路线的核心价值）：原型语义层实现的是**契约**而非性能——`/api/v1/query` 的 DSL schema、`最终 WHERE = RLS ∩ 全局筛选 ∩ Σ cross-filter` 的合成规则、compare_policy 三策略、缓存键四因子，全部按生产语义实现并输出编译产物 SQL 供比对。验证通过后，**契约 + 黄金用例集 + 编译器纯函数逻辑**直接迁入生产实现（Java 或评估 Cube 内核），前端换壳不换协议。

### 4.3 原型 ↔ 生产映射（迁移成本表）

| 层 | 原型（P0） | 生产（设计方案定论） | 迁移成本 |
|----|-----------|---------------------|---------|
| 视图 | vanilla JS（ES Module，每页面一文件） | React 18 + antd 5 + Zustand | 重写视图层；下钻状态机、联动事件协议、URL 编解码为纯逻辑，平移复用 |
| 图表 | 本地 `echarts.min.js` 文件（锁定版本） | ECharts 6（npm 自托管） | **option 资产 100% 复用**；需回归版本差异 |
| 语义层 | Node 零依赖服务：内存数据 + DSL 编译器（纯函数）+ 内存缓存 | Spring Boot 3 / 评估 Cube.js 内核，Doris 执行 | DSL 契约、编译规则、黄金用例集直接迁移；执行器换 Doris |
| RLS | 账号绑定机构节点 → 编译期注入谓词 | RBAC + RLS 元数据库 + 达梦 | 注入点与谓词算法不变，仅元数据存储换 |
| 缓存 | 进程内 Map，键=四因子指纹 | Redis + 本地二级 | 键算法一致 |
| 鉴权 | 演示账号切换器（3 账号） | 统一鉴权 + 审计 | 原型不做真鉴权，仅模拟身份 |

### 4.4 否决的替代方案

| 替代方案 | 否决理由 |
|---------|---------|
| 提前搭 React+Vite+antd 生产脚手架 | 首日就要处理构建链、内网 npm 镜像、依赖固化问题；视图层价值在原型阶段为零，反而拖慢机制验证；且容易诱导"原型代码直接上线"的错误预期 |
| 直接连 Doris 做真栈原型 | 部署/数据导入周期长；本阶段验证的是机制正确性而非性能（见 R3）；等保内网环境未就绪 |

### 4.5 风险与对策

| # | 风险 | 对策 |
|---|------|------|
| R1 | vanilla JS 无组件化，页面逻辑膨胀后失控 | 冻结 3 页面（§5）；每页面一个入口文件 + 共享 `bus.js/state.js/api.js`；任何"想加框架"的冲动触发范围评审而非动手 |
| R2 | 原型编译器（内存执行）与 Doris SQL 方言/语义存在差异 | 编译器产物输出标准 SQL 字符串入日志与黄金用例比对；黄金用例集设计为可在两种执行器上各跑一遍，生产接入 Doris 时全量回归 |
| R3 | 内存数据的性能完全不具代表性 | 已在 §1.3 显式声明：不验证性能。演示时明示"数据为内存种子" |
| R4 | 本地 ECharts 文件版本与生产 ECharts 6 漂移 | 锁定本地文件版本号并在 README/演示话术中登记；生产升级时跑 option 兼容回归 |
| R5 | 双栈并行导致"原型修了、生产没修"的契约漂移 | DSL 契约文档 + 黄金用例集作为唯一共享资产单独管理；任何一侧改动必须走 §2.6 契约变更路径并双侧同步 |
