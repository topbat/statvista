## 一、高危清零（3 项）

### H1–H3 · “命令注入” ×3（smoke.js:26、tests.js:25/26）

**核查结论：误报（模式误判），但已消除触发模式。**

- 全仓库 `grep -rn "execSync|execFile|spawnSync|spawn(|exec("` **零命中** —— 代码中不存在任何子进程调用，构成不了命令注入。
- 扫描器命中的是 `require(path.join(__dirname, '..', 'data', 'facts.json'))`：**动态拼接路径传入模块加载器**，静态分析把它归类为“动态代码执行”。
- **修复**：改为静态字面量 `require('../data/facts.json')`，语义完全等价，动态路径模式消失。

### H4 · 路径穿越（index.js serveStatic）

**核查结论：真实风险面，已在五层加固。**

原实现只有一层 `startsWith` 前缀检查，缺少解码、`..` 段、扩展名与符号链接校验。加固后：

| # | 防线 | 作用 |
|---|------|------|
| ① | `decodeURIComponent` 后再校验，非法编码拒绝 | 挡住 `%2e%2e%2f` 编码变体 |
| ② | 拒绝 `.` / `..` 段（同时识别 `\` 与 `/`） | 挡住 `..%5c` Windows 变体 |
| ③ | `path.resolve` 后根目录边界校验 | 挡住规范化前的前缀伪装 |
| ④ | 扩展名白名单（html/js/css/json/svg/png/ico/woff/map） | 挡住读取 `.md`/`.env`/源码 |
| ⑤ | `fs.realpath` 二次校验 | 挡住符号链接逃逸 |

**实测证据**（加固后，正常资源不受影响）：

| 请求 | 结果 |
|------|------|
| `/`、`/app.js`、`/style.css`、`/assets/echarts.min.js` | **200**（正常） |
| `/../../etc/passwd` | **403** |

| `/%2e%2e/server/index.js`、`/assets/../../server/index.js` | **404**（Node URL 层已规范化，目标不存在 → 零泄露） |

### 附带加固 · 响应安全头

`Content-Security-Policy`（default-src 'self'、object-src 'none'、frame-ancestors 'none'）、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer` —— 即使发生注入，脚本也无法外连或加载第三方资源。

## 二、剩余的 1 项中危（人工确认为误报，保留跟踪）

**M1 · 疑似跨文件污点 → innerHTML（index.js:82 → app.js:1473）**

- **真实数据流**：`/api/v1/meta/metrics` → `dictTableHtml()` / `dictDetailHtml()` → `innerHTML`。
- **人工核查**：两个渲染函数的**每一个远端字段**均经 `esc()` 转义（`code / name / unit / aggType / comparePolicy / formula / numeratorRef / denominatorRef / basisDocNo / ownerDept / updateFreq / dataClass`），URL 参数另经 `encodeURIComponent`。静态分析看不穿函数内部转义，故报警。
- **纵深防御**：CSP `default-src 'self'` 使任何注入脚本无法外连。
- **处置**：不降级为“已通过”，门禁保持**黄**并登记；v0.2 生产化时统一引入 DOMPurify 白名单渲染，届时复扫转绿。

## 三、顺带修掉的真 bug（非安全问题）
